The Context step in the earlier baselines stretched Tone across the row because the span rule counted the legend. That is fixed: even field counts stay in two columns, including Visual and Text. An empty Copy button is the subtle surface, and the badge says “Just started”. Below 520px the storefront cover is 180px. Baselines were refreshed the same day: `npx playwright test --config=playwright.visual.config.js --update-snapshots` — 16 passed. Rewritten: every `en-creative-brief-*`; `en-pdf-storefront-320` and `-768`; and the other 320/768 homepage sections whose pixels had moved. At 1024 and 1920 only the brief changed. Privacy, terms, and success matched.

## Findings

Fixed in the same pass, then the affected snapshots were refreshed.

1. **Sticky prompt bar stays off the first screen.** `.sticky-prompt-bar[hidden] { display: none !important }` so `display: flex` no longer beats the `hidden` attribute. The bar still appears after the reader passes `#block1` at 320 and 768. From 769px it stays `display: none`.

2. **Success download label is white on navy.** `.satellite-main a.satellite-back` keeps inverse text. “Download your PDF” is readable. The header “Back to library” link is unchanged.

3. **320 nav is one row.** Under 480px the three links sit on their own row under the wordmark: Workflows, Brief builder, Pricing. The rule is placed after the base `.site-nav` block so `flex-wrap: wrap` does not win.

## Harness notes

`serve.json` rewrites `/en/` and `/lt/` to `index.html`. On Windows, `serve` otherwise lists the directory and the suite never sees the page. `npm run build` copies that file into `public/`.

The sticky baseline sets `position: relative` only for the shot. A `position: fixed` element screenshot was an empty cream strip.
